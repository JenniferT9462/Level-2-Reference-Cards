Markdown & README

A README is the front page of your repo. GitHub turns its Markdown into headings, lists, links and tables.

# heading**bold**- list[text](url)`code`| table |

Headings and text

# Project name
## Section
### Smaller section

Plain paragraph text.
Leave a blank line between paragraphs.

**bold** and *italic*

Use one # heading at the top, like an <h1>.

Lists

- Bullet
- Another bullet
  - Indented with 2 spaces

1. First step
2. Second step

- [x] Done task
- [ ] Not yet

Links and images

[Live site](https://user.github.io/repo/)

![Screenshot of the signup page](images/screenshot.png)

The image text in [ ] is the alt text. Write what the image shows.

Code

One backtick for code inside a sentence. Three backticks on their own lines for a block.

Run `git status` first.

```bash
git add .
git commit -m "Add README"
```

Tables

Good for an ACP log. The pipes don't need to line up.

| Date  | Commit message      | What I learned |
|-------|---------------------|----------------|
| 10/20 | Add first index.html | git init only once |
| 10/21 | Add README          | -u on first push |

A README outline

# Project name

One sentence: what it is and who it's for.

**Live site:** https://user.github.io/repo/

## Built with
- HTML, CSS, JavaScript

## How to run it
Open `index.html` in a browser.

## What I learned

Check your assignment page for the exact sections it requires.

Common mix-ups

Heading shows as #Title

Put a space after the #.

List runs into the paragraph above

Leave a blank line before the first -.

Image is broken on GitHub

Paths are case-sensitive there. Screenshot.PNG is not screenshot.png.

GitHub doesn't show it on the repo page

Name it README.md and put it in the top folder.
