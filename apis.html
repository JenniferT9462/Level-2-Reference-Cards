Weeks 5–7

APIs & Postman

Read the docs, get the request working in Postman, then write the same request in JavaScript.

GET https://api.example.com/plants?sun=full&page=2

Parts of a request

MethodGET read, POST create, PUT/PATCH update, DELETE remove
Base URLhttps://api.example.com
Endpoint/plants or /plants/42
Query params?sun=full&page=2 filters and options
HeadersExtra info: content type, auth
BodyData you send with POST/PUT, usually JSON

Parts of a response

  • Status code: did it work?
  • Headers: content type, rate-limit info
  • Body: the data, usually JSON

Before you write any code, find the exact field you need in the body. For example, is it data.results[0].name or data.name?

Status codes

CodeMeaningWhose fix?
200 / 201OK / Creatednone
400Bad requestyours: check params
401Not authenticatedyours: missing/wrong key
403Not allowedyours: key lacks access
404Not foundyours: check the URL
429Too many requestswait, then retry
500 / 503Server problemtheirs: try later

Postman workflow Week 5 Day 1

  1. Make a Collection for the project.
  2. Add a request. Pick the method and paste the URL.
  3. Put query params in the Params tab, not by hand.
  4. Click Send. Read the status, then the body.
  5. Save the working request (Ctrl + S).

Postman variables Week 5 Day 2

Set them once in an Environment, then use double curly braces anywhere:

{{baseUrl}}/plants?sun=full
Authorization: Bearer {{apiKey}}

Put keys in the Current value column. That column stays on your computer and isn't shared with the collection.

Where the key goes Week 6 Day 2

Each API's docs say which of these it uses:

Query param?api_key=KEY
Custom headerX-Api-Key: KEY
Bearer tokenAuthorization: Bearer KEY
NoneOpen APIs, no key needed

Postman → fetch

Postman's </> Code button (right side) shows the request as JavaScript fetch code. Compare it with what you wrote:

const url = `${BASE_URL}/plants?sun=full`;
const response = await fetch(url, {
  headers: { Accept: "application/json" },
});

Same method, same URL, same headers. If Postman works and fetch doesn't, one of those is different.

Pagination Week 6 Day 3

APIs send results a page at a time. Look in the docs or the response for something like:

{
  "page": 2,
  "total_pages": 9,
  "next": "https://api.example.com/plants?page=3",
  "results": [ ... ]
}

Disable your Next button when there's no next page, and show "Page 2 of 9".

Rate limits

  • A 429 status means slow down.
  • Check for a Retry-After header. It gives the number of seconds to wait.
  • Disable the button while a request is running, so double-clicks don't send two requests.
  • Tell the user to wait. Don't retry in a loop.

Keep keys secret Week 7 Day 5

Anything in frontend code is public, including GitHub Pages sites and private repos you share. When an API needs a secret key:

  1. A small server (the proxy) on Render holds the key as an environment variable.
  2. Your page calls your proxy. It never sees the key.
  3. The proxy adds the key and calls the real API.
// on the server only
const key = process.env.API_KEY;

Common mix-ups

Pushed a key to GitHub

Deleting the line isn't enough, because it's still in the history. Tell your instructor and get a new key.

401 even though the key is right

It's in the wrong place. Check whether the docs want a header or a query param, and check the exact name.

Works in Postman, fails in the page

Compare URL, method and headers. If the console says CORS, you need the proxy.

undefined on the page

Wrong path into the data. console.log(data) and follow it one level at a time.
