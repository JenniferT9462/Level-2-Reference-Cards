Semantic HTML & Forms

Choose tags for what the content is, so screen readers, search engines and other developers can follow your page.

<header><nav><main><footer><label for>

Page skeleton

<!DOCTYPE html>
<html lang="en">
  <head>
    <meta charset="UTF-8">
    <meta name="viewport"
      content="width=device-width, initial-scale=1">
    <title>Garden Club Signup</title>
    <link rel="stylesheet" href="style.css">
  </head>
  <body>
    <header>...</header>
    <main>...</main>
    <footer>...</footer>
    <script src="script.js"></script>
  </body>
</html>

Without the viewport line, phones zoom out and show a tiny desktop page.

Landmarks

TagUse it for
<header>Logo, site name, intro
<nav>The main group of links
<main>The page's main content (once per page)
<section>A themed group that has its own heading
<article>Something that makes sense alone, like a card or post
<aside>Side info, related to the main content
<footer>Contact, credits, copyright
<div>Only for styling, when nothing else fits

Headings in order

Use one <h1>. Go down one level at a time, and don't skip from h2 to h4. Choose the level by importance, then use CSS to change the size.

<h1>Garden Club</h1>
  <h2>Why join</h2>
  <h2>Sign up</h2>
    <h3>Volunteer times</h3>

A labeled input

The label's for matches the input's id. Clicking the label then focuses the box, and screen readers read the label aloud.

<label for="email">Email</label>
<input type="email" id="email" name="email" required>

name is the key the data is sent under. Without it, the value isn't sent.

Input types

type=Gives you
textPlain text
emailChecks for an @; email keyboard on phones
telNumber pad on phones
numberArrows, min / max
dateA date picker
checkboxYes or no, or pick several
radioPick exactly one (same name)

Also: <select> for a dropdown, <textarea> for long text.

Group radio buttons

<fieldset>
  <legend>Preferred day</legend>
  <input type="radio" id="sat" name="day" value="sat">
  <label for="sat">Saturday</label>
  <input type="radio" id="sun" name="day" value="sun">
  <label for="sun">Sunday</label>
</fieldset>

The <legend> is the question; each label is one answer.

Built-in validation

The browser checks these before it submits. You don't need JavaScript for them.

requiredCan't be empty
minlength="2"At least 2 characters
min="1" max="10"Number range
pattern="[0-9]{5}"Must match, here a 5-digit ZIP code
 
/* style only after the user has typed */
input:user-invalid { border-color: crimson; }

URLs are not secrets

A form with method="get" puts every answer in the address bar, where it's saved in history and can be shared:

signup.html?name=Sam&email=sam%40mail.com

Anything in your HTML, CSS or JavaScript can be read by anyone with View Source. Never put passwords or keys there.

Link or button?

  • <a href> goes somewhere: another page or a section.
  • <button> does something: submit, open, toggle.

Inside a form, a button submits by default. Add type="button" if it shouldn't.

Common mix-ups

Clicking the label does nothing

Its for doesn't match the input's id exactly. Check spelling and case.

Using placeholder as the label

The placeholder disappears when you type. Always add a real <label>.

Every radio can be checked at once

They need the same name to work as one group.

A page made only of divs

Swap in header, main, section and footer. It looks the same and reads better.
